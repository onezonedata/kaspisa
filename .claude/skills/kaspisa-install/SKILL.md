# Установка kaspisa

Правила А1–А13 — в `AGENTS.md` корня репозитория. Здесь только порядок шагов. Команды выполняет агент, если не сказано иначе.

## Перед началом

1. Проверь `id -u`. Если результат 0, остановись и отошли владельца к `docs/install.md`, раздел «Сервер одной командой» (А9).
2. Спроси владельца режим: `local`, `tunnel` (по умолчанию) или `public`. Для `public` нужны домен и e-mail для Let's Encrypt (или `internal` для проверки). Это не секреты.
3. Проверь, что есть `docker compose version`. Если нет, остановись: подготовку сервера владелец выполняет от root (скилл `kaspisa-server`, шаг 1).
4. Проверь переменные оболочки (А13):

   ```
   bash -c 'compgen -e' | grep -E '^(KASPISA_DRY_RUN|KASPISA_VERSION|KASPISA_IMAGE_PREFIX|COMPOSE_PROFILES|COMPOSE_FILE|COMPOSE_ENV_FILES|POSTGRES_.*)$'
   ```

   Команду не заменяй на `compgen -e` без `bash -c`: в zsh она ничего не находит.

   Если вывод не пустой, попроси владельца перезапустить агента в новой оболочке без этих переменных. Значения не выводи.

## Установка

5. Запусти установку в фоне и следи за выводом, пока процесс не завершится: сборка идёт несколько минут. В Claude Code это Bash с `run_in_background`; в других агентах — аналогичный фоновый запуск.

   ```
   bash install.sh tunnel
   ```

   Режим передавай всегда: без него скрипт спросит через `read`. Для `public`:

   ```
   KASPISA_DOMAIN=<домен> KASPISA_CADDY_TLS=<e-mail или internal> bash install.sh public
   ```

6. Проверь результат:
   - код выхода 0;
   - `docker compose -f docker-compose.prod.yml ps`: сервисы в состоянии `running` или `healthy`;
   - `docker compose -f docker-compose.prod.yml ps -a migrate`: статус `Exited (0)`.

7. Остановись и передай владельцу шаги, которые он делает сам:
   - ключ шифрования: `make show-key` в его терминале; сохранить в менеджер паролей, затем очистить экран и историю (`docs/deploy.md`, раздел 4). Агент `make show-key` не запускает;
   - доступ к интерфейсу: команду туннеля и адрес бери из последних строк вывода `install.sh`, после «kaspisa установлена.» (порт по умолчанию 3000, его меняет `KASPISA_WEB_PORT`); в режиме `tunnel` — команда `ssh -L …` на его компьютере, затем адрес из вывода с добавкой `/register`; в `local` — адрес из вывода с добавкой `/register`; в `public` — регистрация через туннель из вывода (`docs/deploy.md`, раздел 3), затем `https://<домен>`;
   - подключение магазина: пароль Kaspi вводится только в интерфейсе (А4).

8. Напомни владельцу, что запись цен выключена (`KASPISA_DRY_RUN=true`) и включает её он сам (А3, `docs/deploy.md`, раздел «Запись цен»).
